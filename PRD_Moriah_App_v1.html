Plataforma de Gestão Moriah

MVP replanejado para gestão de membresia, contribuições, células, eventos e escalas ministeriais, com foco em simplicidade, segurança e uso real pela igreja.

Resumo MVP Módulos Stack Arquitetura Plano Segurança Prompt Claude

1. Resumo Executivo

Decisão principal: começar com um app interno da Igreja Moriah, sem tentar copiar todos os recursos de uma solução grande logo no início.

A plataforma será composta por painel web administrativo e app mobile. O objetivo é reduzir WhatsApp, planilhas, fichas físicas e controles dispersos.

Fonte única

Membros, famílias, células, ministérios, escalas e contribuições em uma base central.

Financeiro organizado

Membros enviam comprovantes pelo app e o tesoureiro valida em fluxo estruturado.

Escalas reais

Escalas por ministério, função, evento e status de confirmação.

2. Escopo do MVP

Incluído

  • Autenticação e permissões
  • Membresia e famílias
  • Células e relatórios simples
  • Financeiro manual com comprovante
  • Extrato individual do membro
  • Escalas de ministérios
  • Django Admin como painel inicial
  • App mobile básico

Fora do MVP

  • OCR automático
  • Pix dinâmico por API
  • Cartão de crédito
  • Conciliação bancária
  • Moriah Kids completo
  • Escola Bíblica completa
  • Chat interno
  • Dashboards avançados

3. Módulos

Membresia

Cadastro de membros, famílias, vínculo com célula, ministérios, status e dados básicos.

Financeiro

Envio de comprovante Pix, preenchimento manual de valor/data/categoria, validação por tesoureiro e extrato individual.

Células

Cadastro de células, líderes, membros, reunião, presença, visitantes e observações.

Escalas

Ministérios, funções, eventos, escala por função, confirmação, recusa e histórico simples.

Eventos

No MVP, eventos servem como base para cultos e escalas. Inscrições e pagamentos ficam para depois.

4. Stack Recomendada

CamadaStack
BackendDjango + Django REST Framework
BancoPostgreSQL
Painel administrativoDjango Admin customizado
MobileReact Native com Expo + TypeScript
Auth mobileJWT com djangorestframework-simplejwt
StorageS3 compatível: AWS S3, Cloudflare R2 ou MinIO em dev
Infra localDocker Compose
Fila futuraCelery + Redis
OCR futuroGoogle Cloud Vision + Tesseract fallback
Pagamentos futuroEfí, Pagar.me ou Mercado Pago
Motivo: o projeto é CRUD administrativo, permissões, relatórios, anexos e workflows. Django acelera muito mais o MVP do que montar tudo manualmente com FastAPI.

7. Segurança e LGPD

  • HTTPS obrigatório em produção.
  • Controle de acesso por perfil.
  • Auditoria de alterações financeiras.
  • Backup automático.
  • Consentimento para armazenamento de dados.
  • Restrição forte sobre dados financeiros individuais.
  • Evitar ranking ou exposição indevida de contribuições.

A plataforma precisa centralizar membros, famílias, células, ministérios, eventos, escalas e contribuições financeiras com envio de comprovantes Pix. O objetivo do MVP é reduzir o uso de WhatsApp, planilhas e fichas manuais.

3. Regras básicas
- Um membro pode pertencer a uma célula.
- Um membro pode servir em vários ministérios.
- Um evento pode ter uma ou mais escalas.
- Uma escala possui assignments por função.
- Um assignment pode ter status: pending, confirmed, declined.
- Uma contribuição pode ter status: pending, approved, rejected, needs_review.
- Uma contribuição pode ter um ou mais anexos.
- O membro só pode visualizar o próprio extrato.
- Tesoureiro e admin podem validar contribuições.

4. APIs REST
Crie endpoints para:
- Login JWT.
- Perfil do usuário logado.
- Listar dados do membro logado.
- Listar extrato do membro logado.
- Criar contribuição com upload de comprovante.
- Listar escalas do membro logado.
- Confirmar escala.
- Recusar escala com justificativa.
- Líder de célula listar membros da sua célula.
- Líder de célula registrar reunião e presença.

5. Django Admin

- Usuários

- Famílias

- Ministérios

No admin de contribuições, destaque status pendente e permita filtro por status, período, membro e categoria.

- Código organizado.
- Tipagem no mobile.
- Serializers claros no backend.
- Permissões explícitas no DRF.
- README com instruções para rodar tudo localmente.
- .env.example completo.
- Dados seed simples para teste local.

8. Primeiro objetivo técnico
A primeira entrega deve permitir o seguinte fluxo funcionando localmente:

- Admin cria um membro no Django Admin.
- Admin cria uma célula e vincula o membro.
- Admin cria um evento/culto.
- Admin cria uma escala e escala o membro em uma função.
- Membro faz login no app.
- Membro vê sua escala.
- Membro confirma ou recusa.
- Membro envia uma contribuição com comprovante.
- Tesoureiro vê a contribuição pendente no admin.
- Tesoureiro aprova a contribuição.
- Membro visualiza a contribuição aprovada no extrato.

Comece criando a estrutura do projeto, arquivos de configuração e models. Depois implemente APIs e telas mobile. Priorize funcionamento real do fluxo acima antes de qualquer refinamento visual.
